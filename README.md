# MedApp — Android-клиент

Мобильный клиент [MedApp](https://github.com/Kert0n/MedApp): учёт домашней аптечки, общие аптечки,
синхронизация офлайн-изменений с [сервером](https://github.com/Kert0n/MedApp-Server).

Сейчас готов фундамент сборки: `minSdk 29`, `targetSdk 37`, каталог версий, внедрение зависимостей,
манифест и проверка на каждый пуш. Продуктового кода ещё нет — экран остаётся пустышкой
на Compose. Что будет дальше и почему именно так — описано целиком, до сигнатур.

## Обращения и изменения

Для дефекта, продуманного изменения или находки безопасности используйте соответствующий шаблон
[GitHub Issues](https://github.com/Kert0n/MedApp-Android/issues/new/choose). PR заполняется по
репозиторному шаблону, ссылается на раздел PLAN/REQ и получает метки областей по изменённым путям.
Клиентские риски и возможные ошибки на границе серверного протокола остаются issue Android-клиента.
Изменение самого API предлагается отдельно в
[MedApp-Server](https://github.com/Kert0n/MedApp-Server/issues/new/choose).

Коротко о продукте: приложение считает **физические упаковки** лекарств — где лежат, сколько
осталось, когда истекают, кому обещаны. Курс лечения расходует не «препарат вообще», а стек
конкретных пачек в заданном порядке. Аптечкой можно поделиться, и тогда пачки живут на сервере —
но срок годности, доза, заметка и цена остаются только на устройстве: [сервер](https://github.com/Kert0n/MedApp-Server)
приватен по замыслу и не хранит ни дат, ни истории приёмов.

## Сборка

```bash
./gradlew assembleDebug
```

Понадобится Android SDK; путь к нему — в `local.properties`, в git этот файл не попадает.

## Контракт сервера

Полный контракт — [open-api.yaml](https://github.com/Kert0n/MedApp-Server/blob/main/open-api.yaml)
в репозитории сервера; его можно открыть, не поднимая приложение.
