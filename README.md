# MedApp — Android-клиент

Мобильный клиент [MedApp](https://github.com/Kert0n/MedApp): учёт домашней аптечки, общие аптечки,
синхронизация офлайн-изменений с [сервером](https://github.com/Kert0n/MedApp-Server).

Сейчас это заготовка из шаблона Android Studio: экран-пустышка на Compose, тема — и модели, с
которых начинается всё остальное.

## Модели

Три слоя, и только один из них точный.

| где | что | насколько всерьёз |
|---|---|---|
| `data/remote/dto` | провод: запросы и ответы сервера | **точно**, поле в поле с контрактом |
| `domain/model` | то, чем разговаривают экраны | заготовка: формы взяты у сервера |
| `data/local/entity` | что помнится без сети | заготовка: ни базы, ни запросов пока нет |

**Провод точен, потому что за неточность отвечает сервер, а не компилятор.** Разойдётся имя поля
— клиент получит 400 или молчаливый `null`, и разбираться придётся в приложении. Поэтому DTO
разбираются строгим `Json`, а `WireContractTest` роняет сборку на неизвестном поле.

Идентификаторы и величины на проводе — строки. Так их и отдаёт сервер: предел `numeric(19, 6)` не
помещается в `Double`, и разбор числом молча округлял бы половину таблетки. В `BigDecimal` и
`UUID` они превращаются на границе с доменом.

Room присутствует одними аннотациями: `@Database` и `@Dao` появятся вместе с хранилищем, тогда же
подключится и KSP.

## Сборка

```bash
./gradlew assembleDebug
```

Понадобится Android SDK; путь к нему — в `local.properties`, в git этот файл не попадает.

## Контракт сервера

Полный контракт — [open-api.yaml](https://github.com/Kert0n/MedApp-Server/blob/main/open-api.yaml)
в репозитории сервера; его можно открыть, не поднимая приложение.
